# ADR 0010: CIRCL 1.6.3 dependency update

- **Status:** Accepted
- **Date:** 2026-08-22
- **Supersedes:** the CIRCL v1.6.1 implementation pin in ADR 0007

## Context

The reviewed go-git main commit selected by ADR 0009 requires `github.com/ProtonMail/go-crypto` v1.4.1 and directly selects `github.com/cloudflare/circl` v1.6.3. Go minimal version selection therefore cannot link that go-git commit while retaining CIRCL v1.6.1. A module `replace` downgrade would make Sphinx's dependency graph differ from the reviewed upstream graph and could compile go-git against an unsupported cryptographic implementation.

## Decision

Sphinx pins `github.com/cloudflare/circl` v1.6.3 with module checksum `h1:9GPOhQGF9MCYUeXyMYlqTR6a5gTrgR/fBLXvUgtVcg8=` and module-file checksum `h1:2eXP6Qfat4O/Yhh8BznvKnJ+uzEoTQ6jVKJRn81BiS4=`.

This dependency update does not create a new Sphinx signature suite or format. `ed25519+mldsa65-v1` retains the exact FIPS 204 ML-DSA-65 API, deterministic signing mode, empty context, binary frame, public-key encoding, signature encoding, fingerprint construction, and requirement that both Ed25519 and ML-DSA-65 verify. Existing known-answer bytes and committed signatures must remain unchanged.

## Evidence

The pinned proclamation/signature known-answer vector must regenerate byte-for-byte under CIRCL v1.6.3. The complete age/SOPS external interoperability suite, all package tests, race tests, module verification, SBOM generation, and release-candidate checks must pass after minimal version selection.

## Consequences

ADR 0007 remains authoritative for the signature construction and wire format; only its CIRCL module pin is superseded. Any output change is a failed migration, not an accepted compatibility change. Future CIRCL updates require the same explicit review and unchanged-vector evidence unless a separately versioned signature-suite transition is designed.
